About the ARQ Simulator Project

A comprehensive Computer Networks Project-Based Learning (PBL) platform for studying transport and data-link reliability protocols.

System Architecture & Discrete-Event Simulation

This simulator uses a deterministic discrete-event simulation engine rather than relying on real-time sleep calls. Real operating system sleep calls introduce non-deterministic execution times, OS scheduling jitter, and high latency during testing. In contrast, our engine manages a simulated clock with millisecond precision, advancing instantaneously from event to event via a priority queue (heapq).

// Discrete Event Scheduler Flow:
[User Configuration (Loss, Delay, Window, Seed)]
    ↓
[Engine Dispatcher: engine.py]
    ↓
[Priority Queue (Min-Heap of SimEvent objects by timestamp)]
    ↓ Event Loop (Process & Schedule Future Events)
    +-- PACKET_SENT → Network Channel (Loss Check & Delay)
    +-- PACKET_RECEIVED → Receiver Logic (Deliver / Buffer / Discard)
    +-- ACK_SENT → Network Channel (Loss Check & Delay)
    +-- ACK_RECEIVED → Sender Window Advance & Timer Reset
    +-- TIMEOUT → Sender Retransmission (Single / GBN / SR)
    ↓
[Metrics Calculator: Throughput, Efficiency, Delivery Ratio]
    ↓
[Structured JSON Response → Frontend Timeline Visualizer]

Key Engineering Design Decisions:

  • Deterministic Reproducibility: Providing a random seed guarantees identical packet and ACK drop sequences across comparative runs.
  • Stale Event Elimination: Timeouts are tracked with monotonic cookie identifiers, ensuring obsolete timer events do not cause improper retransmissions after window advancement.
  • Decoupled Playback: The frontend animation speed (0.5x–4x) is completely separate from simulated network propagation delay. Changing visual speed does not alter computed throughput or efficiency metrics.
  • Robust Metric Formulations: Zero-division guards and strict definitions prevent false 100% metrics on incomplete transfers.
