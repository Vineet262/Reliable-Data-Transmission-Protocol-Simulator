Stop-and-Wait ARQ

The sender transmits one packet and waits for its acknowledgement before sending another packet.

  • Simple implementation with minimal memory
  • Receiver accepts only expected sequence
  • Low channel utilization over high RTT links

Window: N (Sliding) Cumulative ACK

Go-Back-N ARQ

The sender can transmit multiple packets within a sliding window. When a packet is lost, it retransmits the missing packet and subsequent outstanding packets.

  • High pipeline throughput over high-bandwidth links
  • Receiver requires no out-of-order buffering
  • May retransmit correctly received packets
Simulate Go-Back-N
Window: N (Buffered) Individual ACK

Selective Repeat ARQ

The sender retransmits only packets that require retransmission. The receiver can buffer valid out-of-order packets.

  • Maximum transmission efficiency under loss
  • Receiver buffers out-of-order frames
  • Requires individual timer per packet

Sliding Windows

Overcomes the stop-and-wait bottleneck by pipelining up to W packets simultaneously without waiting for individual confirmations before advancing.

Cumulative vs Individual ACKs

Cumulative ACKs (Go-Back-N) confirm all packets up to sequence K. Individual ACKs (Selective Repeat) confirm only the isolated packet K.

Timeouts and Round-Trip Delay

If an acknowledgement fails to return within the timeout threshold, retransmission is initiated to guarantee delivery over lossy channels.

Throughput & Protocol Efficiency

Throughput measures effective payload bits transferred per second. Efficiency is the ratio of useful payload bits to total transmitted bits.
